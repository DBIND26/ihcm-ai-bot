008: 1. What This Build Actually Is
009: This repo is the IHCM AI Command Center Backend Scaffold. It contains:
010: Three Supabase/Postgres migrations (SQL), a seed file with seven example facilities, a v2 coaching/board schema proposal, a legacy schema review, a migration plan, and the Brutal V2 Blueprint that defines the target platform.
011: There is no frontend code, no backend application code, no Python billing engine, and no running tests in this workspace. This document describes exactly what is shipped and what is not.
012: 1.1 What This Build Is Not
013: A previous QA document incorrectly described this repo as a Python/React SNF billing engine with 10,000+ lines and 16 passing tests. That document described a standalone prototype in a separate working directory. It does not describe this repository. This corrected document supersedes it entirely.

144: 4.5 Pre-Hardening Gap: Access Level Without Role
145: FINDING (P0): All data policies resolve to facility scope + access level. The app_role column exists but is never checked in RLS. A billing user and a DON with the same access level see identical rows. This violates HIPAA minimum-necessary.
146: STATUS: Fixed in Migration 3 (202603270001_platform_hardening.sql). See Section 5.

178: 5.2 Cross-Facility Integrity Fix (P1)
179: New trigger check_reimbursement_assessment_facility() fires BEFORE INSERT OR UPDATE on reimbursement_events. If assessment_id is set, it verifies the assessment belongs to the same facility_id. Raises exception on mismatch.
180: 5.3 Auditability Fix (P1)
181: ai_alerts.acknowledged_by_user_id: New UUID FK column to auth.users. Old TEXT column deprecated with COMMENT.
182: audit_events table: Immutable append-only log. No UPDATE or DELETE policies for authenticated role. Columns: event_id, event_ts, user_id, app_role, facility_id, event_domain, event_type, event_subtype, target_table, target_id, detail (JSONB), source_ip, session_id. Indexed on timestamp, user, facility, and domain+type.
