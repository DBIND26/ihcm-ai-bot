019: 1. Purpose & Scope
020: This document is the authoritative specification for the IHCM AI Bot Widget. It serves two purposes: (1) a build blueprint that defines every file, function, and behavior required for the application to work correctly, and (2) a QA review guide that gives an automated or human reviewer everything needed to verify the build against the specification without access to the original author.
021: A QA agent using this document should be able to: open each source file, verify its content against the spec, run each numbered test case, and produce a pass/fail report. No prior context about the project is assumed.
022: What the application does
023: Provides a floating browser-based chat panel with 5 role-specific AI bots for IHCM's clinical and administrative team
024: Each bot carries a complete IHCM-context system prompt and is accessible via a tab at the top of the interface
025: A building selector dropdown injects building-specific context (census, turnaround status, payer, key relationships) into every system prompt at runtime
026: A draft mode toggle changes the output format from conversational answers to formatted documents (Plans of Correction, appeal letters, care plan entries)
027: Conversation history persists across browser sessions via localStorage, restoring the last 40 messages per bot automatically
028: The Anthropic API key is never exposed to the browser — all API calls are proxied through a Vercel serverless function
029: What the application does NOT do
030: Does not connect to live PCC, billing systems, or any IHCM database — bots work from information the user provides in conversation
031: Does not require user login at v1 — URL-based access shared internally
032: Does not persist data to any server or database — all storage is browser-local
033: Does not stream responses — full reply returned before rendering

092: 3. Architecture & Data Flow
093: 3.1  Request lifecycle
094: Every user message follows this exact path. QA agent: trace this flow when verifying functional tests.
095: User types a message and presses Enter or clicks the send button in the browser.
096: App.jsx calls sendMessage(). Appends user message to currentHistory. Sets loading=true. Renders typing indicator.
097: App.jsx POSTs to /api/chat with body: { botId, buildingId, isDraft, messages } where messages is the full conversation array (role + content only, typing flags stripped).
098: Vercel routes /api/chat to api/chat.js serverless function.
099: api/chat.js reads ANTHROPIC_API_KEY from process.env. Looks up bot by botId in BOTS array. Looks up building by buildingId in BUILDINGS array. Assembles system prompt: bot.system + building.context (if selected) + DRAFT_SUFFIX or CHAT_SUFFIX.
100: api/chat.js POSTs to https://api.anthropic.com/v1/messages with the assembled system prompt and sanitized message history.
101: Anthropic returns a response. api/chat.js extracts content[0].text and returns { reply: string } to the browser.
102: App.jsx receives the reply. Removes typing indicator. Appends assistant message to history. Calls saveHistory(botId, updatedHistory) to persist to localStorage. Renders the new bubble.
103: 3.2  Building context injection
104: This is the core intelligence of the building selector feature. QA agent: verify this mechanism in api/chat.js.
105: When buildingId is null or 'none': system prompt = bot.system + CHAT_SUFFIX (or DRAFT_SUFFIX)
106: When buildingId is a valid building ID: system prompt = bot.system + building.context + CHAT_SUFFIX (or DRAFT_SUFFIX)
107: The building.context string is injected between the base system prompt and the mode suffix
108: Building context injection happens server-side in api/chat.js — never in the browser
109: Each building context block starts with 'ACTIVE BUILDING CONTEXT —' so the model can clearly identify it
110: 3.3  Draft mode mechanics
111: Draft mode changes two things: the system prompt suffix and the max_tokens limit. QA agent: verify both in api/chat.js.
112: Chat mode: appends CHAT_SUFFIX ('Respond conversationally and concisely…'), max_tokens: 1000
113: Draft mode: appends DRAFT_SUFFIX ('OUTPUT FORMAT — DRAFT MODE ACTIVE: respond as a structured, professional document…'), max_tokens: 2000
114: Draft mode doubles the token budget because full documents (POCs, appeal letters) require more output
115: In the browser, draft-mode bot messages receive class 'draft-bubble' which applies serif font, amber left border, and cream background
116: Draft-mode bot messages also display a 'Copy document' button that copies the raw text to clipboard
117: 3.4  localStorage persistence
118: Three categories of data are persisted. QA agent: verify all keys in storage.js and their restore logic in App.jsx.
119: localStorage key (prefixed)
120: What it stores
121: Restored on
122: Max size
123: ihcm_bots_history_{botId}
124: Array of message objects {role, content, draft} for that bot. Last 40 messages.
125: App mount (useState initializer)
126: 40 messages per bot
127: ihcm_bots_building
128: String buildingId — the last building the user selected.
129: App mount
130: Single string
131: ihcm_bots_draft_mode
132: Boolean — whether draft mode was active in the last session.
133: App mount
134: Single boolean
135: ihcm_bots_active_bot
136: String botId — the last bot tab the user was on.
137: App mount
138: Single string
139: The storage.js module wraps all localStorage calls in try/catch. If localStorage throws (incognito mode, quota exceeded), it falls back to an in-memory object (inMemory). The application never crashes due to storage errors — it silently degrades to session-only memory.

232: Last message in sanitized array must have role='user'. Violated returns 400.
233: System prompt assembly — exact order
234: systemPrompt = bot.system
235: if (buildingId && buildingId !== 'none') {
236: const building = BUILDINGS.find(b => b.id === buildingId)
237: if (building && building.context) {
238: systemPrompt += '\n' + building.context
239: }
240: }
241: systemPrompt += isDraft ? DRAFT_SUFFIX : CHAT_SUFFIX
242: Message sanitization
243: Filter: only messages with role 'user' or 'assistant' and string content pass through
244: Truncate: each message content is sliced to 8000 characters maximum
245: Limit: only last 20 messages sent to API (context window management)
246: Result array must end with role='user' or request is rejected
247: Anthropic API call
248: Model: claude-sonnet-4-20250514
249: max_tokens: 1000 in chat mode, 2000 in draft mode
250: system: assembled system prompt string
251: messages: sanitized message array
252: API key from process.env.ANTHROPIC_API_KEY — never hardcoded, never in response
