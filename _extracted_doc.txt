1. Purpose & Scope
This document is the authoritative specification for the IHCM AI Bot Widget. It serves two purposes: (1) a build blueprint that defines every file, function, and behavior required for the application to work correctly, and (2) a QA review guide that gives an automated or human reviewer everything needed to verify the build against the specification without access to the original author.
A QA agent using this document should be able to: open each source file, verify its content against the spec, run each numbered test case, and produce a pass/fail report. No prior context about the project is assumed.
What the application does
Provides a floating browser-based chat panel with 5 role-specific AI bots for IHCM's clinical and administrative team
Each bot carries a complete IHCM-context system prompt and is accessible via a tab at the top of the interface
A building selector dropdown injects building-specific context (census, turnaround status, payer, key relationships) into every system prompt at runtime
A draft mode toggle changes the output format from conversational answers to formatted documents (Plans of Correction, appeal letters, care plan entries)
Conversation history persists across browser sessions via localStorage, restoring the last 40 messages per bot automatically
The Anthropic API key is never exposed to the browser — all API calls are proxied through a Vercel serverless function
What the application does NOT do
Does not connect to live PCC, billing systems, or any IHCM database — bots work from information the user provides in conversation
Does not require user login at v1 — URL-based access shared internally
Does not persist data to any server or database — all storage is browser-local
Does not stream responses — full reply returned before rendering

3. Architecture & Data Flow
3.1  Request lifecycle
Every user message follows this exact path. QA agent: trace this flow when verifying functional tests.
User types a message and presses Enter or clicks the send button in the browser.
App.jsx calls sendMessage(). Appends user message to currentHistory. Sets loading=true. Renders typing indicator.
App.jsx POSTs to /api/chat with body: { botId, buildingId, isDraft, messages } where messages is the full conversation array (role + content only, typing flags stripped).
Vercel routes /api/chat to api/chat.js serverless function.
api/chat.js reads ANTHROPIC_API_KEY from process.env. Looks up bot by botId in BOTS array. Looks up building by buildingId in BUILDINGS array. Assembles system prompt: bot.system + building.context (if selected) + DRAFT_SUFFIX or CHAT_SUFFIX.
api/chat.js POSTs to https://api.anthropic.com/v1/messages with the assembled system prompt and sanitized message history.
Anthropic returns a response. api/chat.js extracts content[0].text and returns { reply: string } to the browser.
App.jsx receives the reply. Removes typing indicator. Appends assistant message to history. Calls saveHistory(botId, updatedHistory) to persist to localStorage. Renders the new bubble.
3.2  Building context injection
This is the core intelligence of the building selector feature. QA agent: verify this mechanism in api/chat.js.
When buildingId is null or 'none': system prompt = bot.system + CHAT_SUFFIX (or DRAFT_SUFFIX)
When buildingId is a valid building ID: system prompt = bot.system + building.context + CHAT_SUFFIX (or DRAFT_SUFFIX)
The building.context string is injected between the base system prompt and the mode suffix
Building context injection happens server-side in api/chat.js — never in the browser
Each building context block starts with 'ACTIVE BUILDING CONTEXT —' so the model can clearly identify it
3.3  Draft mode mechanics
Draft mode changes two things: the system prompt suffix and the max_tokens limit. QA agent: verify both in api/chat.js.
Chat mode: appends CHAT_SUFFIX ('Respond conversationally and concisely…'), max_tokens: 1000
Draft mode: appends DRAFT_SUFFIX ('OUTPUT FORMAT — DRAFT MODE ACTIVE: respond as a structured, professional document…'), max_tokens: 2000
Draft mode doubles the token budget because full documents (POCs, appeal letters) require more output
In the browser, draft-mode bot messages receive class 'draft-bubble' which applies serif font, amber left border, and cream background
Draft-mode bot messages also display a 'Copy document' button that copies the raw text to clipboard
3.4  localStorage persistence
Three categories of data are persisted. QA agent: verify all keys in storage.js and their restore logic in App.jsx.
The storage.js module wraps all localStorage calls in try/catch. If localStorage throws (incognito mode, quota exceeded), it falls back to an in-memory object (inMemory). The application never crashes due to storage errors — it silently degrades to session-only memory.

switchBot(id)
Sets activeBotId to id
Clears inputText
Calls saveActiveBot(id)
Focuses textarea after 50ms (setTimeout)

sendMessage(overrideText?)
Reads inputText or overrideText. Returns early if empty or loading.

Sets loading = true
Creates userMsg = { role: 'user', content: text }
Appends userMsg and a typing placeholder to currentHistory via setHistories
Calls fetch('/api/chat', { method: 'POST', body: JSON.stringify({ botId, buildingId, isDraft, messages }) })
messages array is currentHistory with userMsg appended, with typing objects filtered out, role+content only
On success: removes typing placeholder, appends { role: 'assistant', content: reply, draft: isDraft }
On error: appends { role: 'assistant', content: 'Connection error. Please try again.', draft: false }
In both cases: calls saveHistory(activeBotId, finalHistory), sets loading = false, focuses textarea
handleBuildingChange(e)
Sets buildingId = e.target.value
Calls saveBuilding(e.target.value)
Does NOT clear history — building change takes effect on the next message sent
handleDraftToggle()
Toggles isDraft boolean
Calls saveDraftMode(!isDraft)
Empty state starters immediately update to show draftStarters when isDraft becomes true
handleClearHistory()
Calls window.confirm('Clear conversation history for this bot?')

4.3  MessageBubble component
Props: msg (message object), bot (bot definition), isDraft (boolean)
Renders user messages right-aligned with gray avatar labeled 'You'
Renders bot messages left-aligned with colored avatar using bot.avatar initials
Applies class 'draft-bubble' to bot messages when isDraft=true AND msg.draft=true
Renders typing messages with class 'typing' and text 'Thinking…'
Renders a 'Copy document' button below draft-mode bot messages. Button uses useCopy hook. Shows 'Copied!' for 2 seconds after click.
All message content is passed through renderMarkdown() before dangerouslySetInnerHTML
renderMarkdown(text) — inline function
Step 1: HTML-escapes &, <, > to prevent XSS
Step 2: Replaces **text** with <strong>text</strong>
Step 3: Replaces *text* with <em>text</em>
Step 4: Replaces \n with <br/>
Returns HTML string. Never executes script. No third-party markdown library needed.
4.4  EmptyState component
Props: bot, isDraft, onStarter
Shows bot avatar circle (using bot.colorBg and bot.color), bot name, bot desc
When isDraft=true: shows amber notice 'Draft mode on — responses will be formatted documents'
Shows 4 starter buttons from bot.starters (chat mode) or bot.draftStarters (draft mode)
Clicking a starter calls onStarter(text) which calls sendMessage(text) directly
4.5  api/chat.js — serverless function spec
CORS handling
ALLOWED_ORIGINS = ['https://ihcm-bots.vercel.app', 'http://localhost:5173', 'http://localhost:4173']
If request origin is in ALLOWED_ORIGINS: set Access-Control-Allow-Origin header to that origin
If request origin is NOT in the list: no CORS header set — browser blocks the request
OPTIONS preflight: return 200 immediately with CORS headers
Request validation
Method must be POST. All other methods return 405.
Body must parse to valid JSON. Invalid JSON returns 400.
botId must be a string matching a bot in BOTS array. Unknown botId returns 400.
messages must be an array with at least 1 element. Missing or empty returns 400.
Last message in sanitized array must have role='user'. Violated returns 400.
System prompt assembly — exact order
systemPrompt = bot.system
if (buildingId && buildingId !== 'none') {
const building = BUILDINGS.find(b => b.id === buildingId)
if (building && building.context) {
systemPrompt += '\n' + building.context
}
}
systemPrompt += isDraft ? DRAFT_SUFFIX : CHAT_SUFFIX
Message sanitization
Filter: only messages with role 'user' or 'assistant' and string content pass through
Truncate: each message content is sliced to 8000 characters maximum
Limit: only last 20 messages sent to API (context window management)
Result array must end with role='user' or request is rejected
Anthropic API call
Model: claude-sonnet-4-20250514
max_tokens: 1000 in chat mode, 2000 in draft mode
system: assembled system prompt string
messages: sanitized message array
API key from process.env.ANTHROPIC_API_KEY — never hardcoded, never in response

8. Security Specification
Security is non-negotiable. Three of the 47 test cases are marked BLOCKER — if any fail, deployment must halt.
8.1  API key protection — BLOCKER
ANTHROPIC_API_KEY must only exist in process.env on the Vercel serverless function
The string 'sk-ant-' must not appear in any file under /src/, /public/, or /dist/
The API key must not appear in any HTTP request headers or body visible in the browser's Network DevTools tab
The API key must not appear in the page source, any JS bundle, or any JSON response
Verification: open Chrome DevTools → Network → filter by 'chat' → inspect the POST request → confirm x-api-key header is NOT present in the request from the browser
8.2  CORS restriction
api/chat.js only sets Access-Control-Allow-Origin for origins in ALLOWED_ORIGINS
ALLOWED_ORIGINS must contain exactly: 'https://ihcm-bots.vercel.app', 'http://localhost:5173', 'http://localhost:4173'
A request from any other origin must not receive a CORS header and must be blocked by the browser
Verification: open DevTools console on a different website, run fetch('https://ihcm-bots.vercel.app/api/chat', {method:'POST',...}) — must fail with CORS error
8.3  Input sanitization
All user-supplied content (message text) goes through HTML entity escaping in renderMarkdown() before any DOM insertion
dangerouslySetInnerHTML is only used with the output of renderMarkdown() — which escapes &, <, > before any other processing
XSS test: send message containing '<script>alert(1)</script>' — must render as literal text, not execute
Message content is truncated to 8000 characters per message in api/chat.js before sending to Anthropic
